# 升级、备份与恢复

## 自动升级流程

打开旧图库时，FR_Imageprompt 在显示主窗口前执行：

1. 读取旧数据库版本，并拒绝用旧程序打开更高版本数据库。
2. 检查图库写权限、可用空间和 `PRAGMA quick_check` 完整性。
3. 在 `backups/upgrade/v旧版本-to-v新版本-时间/` 保存设置快照与备份清单。
4. 通过 SQLite Backup API 在 `backups/database/` 创建一致的数据库备份。该备份包含提示词、分类、标签、用户元数据、收件箱、AI 队列和画板。
5. 每个迁移步骤单独事务提交，并把当前阶段写入 `backups/upgrade/current.json`。
6. 迁移后再次检查完整性，显示升级版本和备份目录。

整个流程不移动、删除或覆盖 `originals` 与 `thumbnails`。

## 崩溃后如何判断

- 数据库迁移已经提交，只差最终验证：下次启动继续检查，验证通过后完成升级。
- 迁移尚未完成或验证失败：自动用升级前数据库和设置快照回滚。
- 回滚会保留失败数据库副本在该次升级目录中，便于诊断。
- 回滚不处理图片文件，因此迁移期间由外部方式新增的图片文件仍保留。若它们没有数据库记录，可使用图库检查工具确认孤立文件，不要直接删除。

## 手工恢复

1. 完全退出 FR_Imageprompt，包括托盘进程。
2. 复制整个图库文件夹到另一个磁盘作为额外保险。
3. 打开最新 `backups/upgrade/.../upgrade-state.json` 和 `backup-manifest.json`，确认来源版本。
4. 优先重新启动当前版本，让自动恢复完成。
5. 自动恢复仍失败时，保留现状并导出诊断包。不要自行覆盖数据库；由支持人员根据 `DatabaseBackupPath` 恢复。

不要用空数据库覆盖旧库，不要删除 `promptvault.db-wal`/`promptvault.db-shm` 后继续写入，也不要把备份数据库直接放进正在运行的图库。

## 验证恢复结果

- 主图库数量、搜索、分类和标签正常；
- 待补收件箱仍可打开；
- AI 待校正状态和画板布局仍在；
- `originals` 文件数量不减少；
- 应用显示的升级版本与备份清单一致。
