## 1. 已确认的产品决策

- 一份许可证绑定一台 Windows 电脑，不绑定程序解压目录，也不绑定单个图库。
- 许可证默认永久；签发时可选择一年有效期。
- 没有许可证、许可证损坏、设备不匹配、版本不匹配或已过期时，主程序完全不能进入。
- V2 许可证允许当前和后续全部 V2.x 更新；未来 V3 是否复用许可证另行决定。
- 采用完全离线的 ECDSA P-256 数字签名；用户程序只内置公钥，签发私钥不进入源码、Git、用户体验包、日志或诊断包。
- 继续交付免安装、self-contained、single-file 的 `FR_Imageprompt.exe`；授权机制不要求安装器、账号、网络或付费服务。
- 离线永久许可证不能远程撤销，这是本方案明确接受的边界；需要撤销能力时再引入在线授权服务。

## 2. 权威用户流程

### 2.1 收件人首次使用

1. 解压并运行 `FR_Imageprompt.exe`。
2. 程序在任何图库初始化之前计算匿名设备请求码并显示“需要许可证”窗口。
3. 收件人复制请求码发给授权人。
4. 授权人使用独立的 `FR_LicenseManager.exe`，填写使用人、请求码和期限，生成 `.frlicense` 文件。
5. 收件人在许可证窗口导入文件；验证通过后立即进入程序，不要求联网或重启。
6. 导入后的许可证保存在 `%LOCALAPPDATA%\FR_Imageprompt\license.frlicense`。移动程序目录、更新同一 V2.x 程序或切换图库不需要重新授权。

### 2.2 授权人签发

1. `FR_LicenseManager.exe` 只作为授权人私有工具，不进入用户体验包。
2. 签发私钥保存在 Windows 凭据管理器目标 `FR_Imageprompt/LicenseAuthority/V2`。
3. 工具输入使用人名称、设备请求码，并选择“永久”或“一年”。
4. 工具生成单个可发送的 `.frlicense` 文件；文件不包含私钥和硬件原始标识。
5. 私钥丢失不影响已经签发的许可证，但会失去继续签发能力；工具必须提供加密备份与恢复入口。

## 3. 数据与安全契约

### 3.1 设备请求码

- 原始输入只在本机内存中短暂存在：Windows `MachineGuid`、系统卷序列号、产品域分隔符。
- 对规范化输入执行 SHA-256，只使用摘要生成分组可读的请求码。
- 许可证和日志只保存请求码，不保存 MachineGuid、磁盘序列号、用户名、MAC 地址或本机路径。
- Windows 重装、系统盘克隆/更换等导致请求码变化时，由授权人手工重新签发；程序不自动迁移授权。

### 3.2 许可证载荷

签名载荷至少包含：

- `schemaVersion`
- `product`
- `licenseId`
- `licensee`
- `deviceCode`
- `issuedAtUtc`
- `expiresAtUtc`（永久许可证为 `null`）
- `minimumMajorVersion`
- `maximumMajorVersion`
- `keyId`

外层文件只包含固定顺序序列化后的载荷、ECDSA-SHA256 签名和密钥 ID。任何字段修改都会使签名失效。

### 3.3 启动边界

- 授权验证必须发生在 `AppSettings.Load`、图库路径选择、`LibraryRepository.InitializeAsync`、数据库迁移、剪贴板监听、外部索引、AI Worker 和主窗口创建之前。
- AI Worker 同样必须验证许可证；无效时无界面退出，不处理图片或队列。
- 显式 `--license <path>` 只允许指定另一份仍需正常签名且设备匹配的许可证，用于隔离真界面验证，不是绕过开关。
- 不实现测试后门、环境变量绕过、隐藏万能码或失败后进入只读模式。

### 3.4 私钥边界

- 私钥不允许出现在仓库目录、Git 历史、构建输出、用户 ZIP、测试报告、日志或诊断包。
- 私钥只以 Windows 凭据管理器密文保存；`FR_LicenseManager.exe` 仅在签名操作期间将其载入内存，并在使用后清零可清零的字节缓冲。
- 私钥备份必须使用口令派生密钥和认证加密，禁止导出明文 PKCS#8。
- 用户体验包文件审计必须确认不含 `FR_LicenseManager.exe`、私钥、个人许可证或签发配置。
