**1. 画板超过 50 步后的撤销错误**

定位：`src/PromptVault.App/BoardWindow.xaml.cs:1187`，`CommitSceneHistorySnapshot`。

代码压栈后使用 `_undo.Reverse().Take(50).Reverse()`，既丢掉最新记录，又在重新 Push 时反转保留记录。通过反射调用实际生产方法，使用只含历史栈的内存对象（跳过窗口构造，不访问数据库），得到：

- 第 50 次：栈顶为第 50 份快照，符合预期。
- 第 51 次：应为第 51 份，实际为第 1 份。
- 第 52 次：应为第 52 份，实际为第 50 份。

修复方向：保留最新 50 份，并按旧到新重新压栈，使最新记录始终位于栈顶。增加 49/50/51/52/100 次边界回归及撤销、重做往返；区分本入口的画板 Ctrl+Z 与前一份报告的“撤销收录”。大画板历史存储可再评估差量化，但不应与这一小范围正确性修复捆绑重构。

复现材料：`.audit/2026-09-07/BoardHistoryProbe.cs`、`board-history-reproduction.json`。运行参数为现有 AuditProbe 的输出目录加 `--board-history`。本轮探针构建和运行成功；调用生产方法不等于完成真实画布输入验收。

**2. 保存失败后的恢复与反馈不完整**

定位：`BoardWindow.xaml.cs:1107` 的 `SaveSelectedItemsAsync`、`BoardWindow.Crop.cs:53` 的 `CommitCropModeAsync`、`BoardWindow.xaml.cs:1626` 的 `OnClosing`。

图片批量保存捕获异常后只显示“保存失败”，不向调用者返回失败状态。裁剪提交随后无条件结束裁剪会话，并再次显示“裁剪已保存”，覆盖错误。图片位置、大小等保存失败后也没有统一的待保存集合；切换画板重新加载时会用数据库旧状态替换内存修改。关闭路径主要提交裁剪和相机，最终保存失败只写日志，仍允许关闭。

修复方向：保存返回明确结果；只有成功才显示成功、清除待保存状态。按画板 ID 和项目 ID 保留失败修改，提供简洁的持久错误提示及重试入口。切换画板或关闭时先完成待保存提交，失败则保留工作内容并让用户明确选择重试或放弃。成功场景继续保持安静、无额外弹窗。便签的单项、批量和离焦保存一起纳入相同错误反馈边界。

验收：在合成图库中注入图片/便签写入失败，确认不出现假成功；恢复可写后重试有效；切换、关闭、撤销和重做不能默默丢失修改。手势中仍保持零数据库写入，松手只提交一次。

**3. 透明窗口交接的重复触发与继续操作**

定位：`App.xaml.cs:391` 的 `SwitchMainWindowAsync`、`MainWindow.xaml.cs:207` 的 `CreateSnapshot`、`:411` 的 `CancelSnapshotTransfer`、`:339` 的旧窗清理；`ViewModels.cs:684` 的 `GalleryRow.Release`。

第一次切换捕获快照时将 `_galleryRowsTransferredOut` 设为 true，新窗复用同一批 GalleryRow。等待新窗准备期间旧窗仍可接收输入。第二次调用进入 `_mainWindowSwitchActive` 分支，会对当前旧窗调用 `CancelSnapshotTransfer`，把标志设回 false。第一次随后成功关闭旧窗时，就会对共享行调用 Release，取消缩略图任务并清空 Items。

修复方向：在创建快照之前统一检查/合并重复请求；由一次交接会话管理行资源转移，不能让另一次被拒绝的请求取消正在进行的交接。可暂时禁用切换入口，或在当前交接完成后处理最终目标状态；不要用全局冷却时间干扰正常切换。

另一个应纳入回归的边界：快照固定了当时的滚动位置、搜索、选择和窗口几何，而旧窗预热期间仍可继续操作。需明确交接前同步最新状态，或只在极短的交接阶段保护相关输入；防止用户刚滚动后又回到旧位置。此项尚未做独立 UI 复现，不混入历史 160 次无交互切换基线的通过结论。

验收：正常切换、快速双击/连按、切换中滚轮/选择/改窗、准备超时分别覆盖；成功时共享行不被释放，失败时旧窗可继续使用。保留两帧稳定、零重排、滚动锚点和退役窗口回收门禁。

**4. 主图库拖动窗口的高 DPI 手感**

定位：`src/PromptVault.App/MainWindow.Transparent.cs:110`。`PointToScreen` 的物理像素差直接加到 WPF 的 Left/Top（DIP）。画板对应的 `BoardWindow.Commands.cs:149` 已将差值除以 DPI 比例，两个窗口的手感因此不一致。

修复方向：统一物理像素到 DIP 的转换，验证 100%/150%/200%、跨不同 DPI 屏幕、最大化恢复和鼠标捕获中断。这里修复的是主图库窗口拖动，不改变画板普通右拖平移、Ctrl+右拖整窗移动的现有职责。

**可选体验增强（尚未形成实施决定）**

1. 画板参考锁定。提供“只看不编辑”的可选状态，允许缩放、平移、查看原图与聚焦，阻止误移动、缩放对象、裁剪和删除。适合一边参考一边在其他软件工作；保持一个清楚的解锁入口，不引入默认鼠标穿透。全板锁定可先于逐对象锁定，降低复杂度。
2. 多张图片排版。增加所选图片的边缘对齐、水平/垂直等间距和按原始比例排列，作为显式命令，一次操作对应一次撤销。现有便签“对齐”只改变文字对齐方式，不是图片位置对齐；图片已有分组、层级和共同缩放，不重复增加这些功能。

建议先完成四项正确性修复，再根据用户主要使用方式选一项体验增强。保留沉浸画布、已有快捷键和顶部栏规则；不增加常驻大型面板。实施前在适用蓝图追加新的步骤和验收标准，本轮不改写已完成阶段的历史结果。
