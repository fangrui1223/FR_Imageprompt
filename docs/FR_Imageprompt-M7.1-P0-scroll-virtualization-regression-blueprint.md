# FR_Imageprompt 2.0 — M7.1 P0 滚动与虚拟化回归修复蓝图

> 文档状态：已完成
> 建档日期：2026-07-30
> 当前分支：`codex/m1-foundation`
> 建档基线：`0036f0a`（`Complete M7 interaction refinement`）
> 适用版本：M7 最终体验包之后的 P0 回归修复
> 上游总蓝图：`docs/FR_Imageprompt-2.0-implementation-blueprint.md`
> M7 历史账本：`docs/FR_Imageprompt-M7-interaction-refinement-blueprint.md`

本文档只处理 M7 最终体验版暴露出的四个紧密相关问题：

1. 瀑布流滚动后出现局部列空白或整屏空白。
2. 拖动滚动条时画面不实时跟随，松手后才跳转。
3. 标题长期显示“已加载 240”，用户难以确认其余图片是否存在。
4. M7 真瀑布流比 M6 主观明显更卡。

本文档不继续扩写 M7 总账本，不进入新的产品功能阶段，不改 AI、收录、详情、透明模式和画板业务。完成后，新对话只需先读 `AGENTS.md`、本文件和本文件直接指向的代码，不需要重新加载完整 M7 历史。

## 0. 接手摘要

### 0.1 已确认事实

- 发布目录中的 M7 `PromptVault.exe` 与用户解压体验的 EXE 字节数和 SHA-256 完全一致，排除解压错误和版本错用。
- 用户图库总数为 550；程序初始页为 240。实测到达底部后依次变为 480、550，图片记录没有丢失。
- 当前标题中的“已加载 240”来自 `GalleryVirtualizationPolicy.PageSize = 240`，属于 M1 稳定键分页设计。
- `RowsList` 明确设置 `ScrollViewer.IsDeferredScrollingEnabled="True"`，因此拖动滚动条滑块时内容不会实时移动。
- M7 用 `VirtualizingMasonryPanel` 替换 M6 的 `VirtualizingStackPanel`，并把真瀑布流改为每张图片一个 `GalleryRow`/WPF 容器。
- 面板滚动测量会遍历项目计算 extent 和实现范围；离区容器会回收，`GalleryRowUnloaded` 会释放卡片并取消缩略图。
-滚动事件同时触发 220ms 高运动图片提交保护；大跨度跳转越过预取区时，新容器可能先呈现空背景，停止后才收到缩略图。
- M7 虚拟化探针使用简化色块和程序化小步滚动，没有覆盖真实卡片模板、缩略图释放/重用、滚动条大跨度拖动和视口非空断言。
- 诊断期间应用日志没有异常；问题属于布局/呈现协议回归，不是数据库读取失败。

### 0.2 根因分层

| 层级 | 根因 | 用户表现 |
| --- | --- | --- |
| 输入 | 开启延迟滚动 | 滑块移动时图库不动，松手才跳转 |
| 布局 | 面板每次测量扫描当前全部项目 | 数据越多，滚动主线程工作越多 |
| 虚拟化 | 真瀑布流每张图片一个容器，跳转时集中回收/生成 | 中间列空白、整屏空白、卡顿 |
| 图片呈现 | 离区立即取消缩略图，高运动期间又暂停新图片提交 | 停止后才逐步出现图片 |
| 分页 | 首批固定 240，接近当前 extent 末端才取下一页 | 用户误以为只展示了 240 张 |
| 验证 | 简化探针只检查容器少和帧率，不检查目标视口有图 | 空白画面也可能得到漂亮帧率 |

### 0.3 不可回退边界

- 保留连续最短列，不恢复 M6 的周期分段列高重置。
- 保留完整原始比例，不裁切裤子长图、全身图或超宽图。
- 保留稳定键分页，不在启动时一次创建 550 或 30,000 个卡片 ViewModel。
- 保留 480/720/1080/1600px 解码档位、四工作线程、有界队列和缓存预算。
- 保留搜索/分类的旧画面保持和近黑帧为 0 协议。
- 不使用淡入、遮罩或延迟滚动掩盖空白。
- 不删除、重建或迁移真实图库。
- 所有后续真界面测试必须使用显式 `--settings`、工作区合成图库并关闭剪贴板监听。
- 不把真实图库路径、用户图片、提示词、密钥或本机绝对路径写入提交文件。

### 0.4 完成定义

只有同时满足以下条件才可将 M7.1 标记完成：

- 滚动条滑块拖动时，图库位置实时跟随。
- 滚轮、PageUp/PageDown、Home/End 和滑块 0/25/50/75/100% 跳转均无局部列空白或整屏空白。
- 目标视口预期相交项目与实际实现项目差异为 0。
- 550 条等价合成图库可从 240 自动追加到 480、550，零重复、零遗漏。
- 30,000 条只实现视口和受控缓存范围，不线性创建容器。
- 4K、150%、59Hz 标准滚动 P95 不高于 16.949ms，P99 不高于 33.064ms。
- 近黑帧 0；缩略图缓存不超过既定预算；后台解码并发不超过 4。
- Debug/Release 构建无错误，全部自动化测试通过，发布包只包含最终 EXE。
