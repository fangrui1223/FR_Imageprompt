## 0. 新对话接手摘要

### 0.1 用户已确认的最终目标

1. 图片被单选后必须能够直接拖动四角改变尺寸；默认保持图片当前可见比例。
2. `Shift+拖角`才允许图片宽高独立变化，形成拉伸变形。
3. `Alt+拖角`从图片中心缩放；`Shift+Alt+拖角`从中心自由变形。
4. 便签被单选后必须能够直接拖动四角自由改变宽高，文本实时重排；`Alt+拖角`从中心调整便签。
5. 手柄必须既克制又真正可抓取，具有悬停、按下、拖动中的明确反馈；不能只在自动化树中存在。
6. `Ctrl+鼠标右键拖动`移动整个画板窗口在显示器上的位置，不再平移画布。
7. 窗口最大化时触发 `Ctrl+右键拖动`，先按指针相对位置恢复到上次窗口尺寸，再继续拖动整个窗口。
8. 中键、`Alt+左键`继续平移画布；普通右键短按继续打开上下文菜单。
9. 裁剪只允许单选一张图片后从“右键 → 裁剪 → 裁剪模式”进入。
10. 裁剪时图片对象的外框、位置、尺寸和旋转全部固定；不显示变换手柄。
11. 鼠标位于图片框内时，滚轮以鼠标位置为锚放大/缩小框内图片，左键拖动框内图片改变显示区域。
12. 框内图片不得缩小或拖动到露出透明区、黑边或画板背景；最大倍率为最小覆盖倍率的 8 倍。
13. 裁剪模式内的滚轮和左键只作用于框内图片；鼠标在框外时画布恢复正常行为。
14. `Enter`、双击图片、右键“完成裁剪”或点击框外保存并退出；`Esc`取消并恢复进入前状态。
15. 切换画板或关闭窗口时完成当前裁剪，避免已明确调整的结果静默丢失。
16. “重置裁剪”恢复当前外框下居中且不露空白的最小覆盖倍率；若外框比例与原图一致，则恢复完整原图。
17. 一次缩放、便签调整或裁剪会话只产生一条撤销记录；手势过程中不得逐帧写 SQLite。
18. 不提交、不推送、不打包，除非用户在实施对话中另行明确要求。

### 0.2 2026-08-02 真实界面观察

- Computer Use 唯一定位用户当前打开的自由画板，只进行了选择、打开右键菜单和退出菜单；未拖动、未执行裁剪、未保存、未修改真实画板数据。
- 当前画板为 67% 缩放。单选图片后自动化树出现四角和四边共八个 `Thumb`，屏幕上只显示约 12 DIP 圆点，缺少悬停放大、按下态和拖动方向反馈。
- 顶部提示仍显示“`Ctrl+右键平移`”，与最新确认的“移动整个窗口”语义冲突。
- 图片右键“裁剪”仍提供“裁剪模式、横向收紧、纵向收紧、重置裁剪”；没有框内滚轮缩放、框内拖动、完成和取消的可发现入口。
- 未对用户当前画板执行任何会写数据库的动作；该窗口只作为可用性证据，不作为自动化验收夹具。

### 0.3 当前实现审计结论

- `BoardTransformEngine.ResizeBounds` 已包含等比、Shift 自由和 Alt 中心几何；`BoardWindow.Transforms.cs` 也读取 `Keyboard.Modifiers`，但现有诊断主要验证核心结果、手柄数量和持久化，没有完成真实指针从命中、捕获、移动到松开的端到端证明。
- 图片共同选择框使用一个覆盖层，手柄位于屏幕空间；M8.1 让覆盖层空白穿透后恢复图片拖动，但仍需重新验证子元素命中、Z 顺序、鼠标捕获、缩放后定位和旋转对象的手柄位置。
- 便签手柄嵌在便签视觉树中，当前直接自由改变宽高并立即保存，但没有统一的便签撤销快照；需与图片手势形成一致闭环。
- `BoardInteractionEngine.ShouldPanCanvasWithRightDrag` 明确把 Ctrl+右键判为平移画布，属于产品语义错误，不是提示文案问题。
- 旧裁剪用四角增减 `CropLeft/Top/Right/Bottom`，拖动过程中不断移除并重建选中图片，再异步加载裁剪位图；旧请求可能晚到并覆盖新状态，且交互模型与用户确认目标完全不同。
- 现有四个裁剪字段已经是规范化源图矩形边界，能够继续保存新框内裁剪结果；M8.2 默认不做数据库迁移。

### 0.4 明确不进入本阶段的 PureRef 能力

- 不实现完整快捷键编辑器。
- 不引入 PureRef 场景文件格式或跨软件兼容。
- 不加入自由绘制、箭头、矩形标注、画板导出或跨画板复制。
- 不加入组内双层编辑、多便签共同选择或全新图层面板。
- 不新增图片翻转、透视变形或网格扭曲；没有明确数据语义前不在菜单中预放空入口。
- 不改变主图库、剪贴板收录、AI、瀑布流、详情侧栏或透明模式。

## 1. M8.2 权威交互契约

### 1.1 图片和多选变换

| 操作 | 结果 |
| --- | --- |
| 单击图片 | 单选图片，显示四个角手柄 |
| 拖动图片内部 | 移动所选图片；多选时共同移动 |
| 拖动四角 | 保持当前可见比例，锚定对角缩放 |
| `Shift+拖角` | 宽高独立变化，允许拉伸变形 |
| `Alt+拖角` | 保持比例并以选择中心缩放 |
| `Shift+Alt+拖角` | 以选择中心自由改变宽高 |
| 多选拖角 | 按共同外框、共同锚点和相同 X/Y 比例更新位置与尺寸 |
| 右键“重置尺寸” | 单图按自然比例恢复推荐尺寸并保持中心；多图逐项恢复自然比例 |

规则：

- 图片默认只显示四角手柄；M8.1 的四边单轴手柄退出日常界面，避免与“Shift 才允许拉伸”冲突。
- 命中区目标为 28 DIP；视觉圆点空闲 14 DIP、悬停或拖动 18 DIP，始终按屏幕尺寸呈现，不随画布缩放。
- 旋转对象的手柄跟随旋转后的真实四角，而不是轴对齐外包围盒的四角；多选继续使用共同外框。
- 手柄命中必须高于图片和选择描边，但选择框空白仍穿透到图片本体。
- 按下手柄后由手柄持有鼠标捕获，直到松开、Esc、失焦或窗口关闭；中途不得转成图片移动、框选或相机平移。
- 修饰键在拖动过程中实时生效；按下或松开 Shift/Alt 后从同一手势初始快照重新计算，不能累计漂移。
- 反向拖过最小尺寸时钳制到最小边，不翻转、不产生 NaN/Infinity、不跳到对侧。

### 1.2 便签变换

| 操作 | 结果 |
| --- | --- |
| 单击便签非编辑区 | 选中便签，显示四角手柄 |
| 拖动便签标题区 | 移动便签 |
| 拖动四角 | 自由改变宽高，文本实时重排 |
| `Alt+拖角` | 以便签中心自由改变宽高 |
| 右键“重置尺寸” | 恢复 300×220 DIP，并保持中心 |

规则：

- 便签不套用图片比例锁定；文本容器默认自由调整宽高更符合用途。
- 最小尺寸为 120×100 DIP；滚动条、文本焦点和输入法不因缩放手势丢失。
- 便签手柄使用与图片一致的 28 DIP 命中区和悬停/按下反馈。
- 便签移动、缩放、重置必须进入统一撤销/重做时间线，并在重启后恢复。

### 1.3 窗口拖动与画布平移

| 操作 | 窗口化 | 最大化 |
| --- | --- | --- |
| 普通右键短按 | 打开上下文菜单 | 打开上下文菜单 |
| 普通右键拖动 | 保留 M8：移动窗口 | 保留 M8：平移画布 |
| `Ctrl+右键`短按 | 不打开菜单、不移动 | 不打开菜单、不移动 |
| `Ctrl+右键`拖动 | 移动整个窗口 | 先还原窗口，再继续移动整个窗口 |
| 中键拖动 | 平移画布 | 平移画布 |
| `Alt+左键`拖动空白 | 平移画布 | 平移画布 |

规则：

- Ctrl+右键的 6 DIP 阈值只区分“未形成拖动”和“窗口拖动”，绝不进入画布平移。
- 最大化还原拖动使用上次有效 `RestoreBounds`，以指针在窗口中的相对 X 位置保持抓手位置，符合 Windows 标题栏拖动直觉。
- 使用屏幕物理坐标和当前显示器 DPI 完成跨显示器移动；支持负坐标显示器。
- 窗口移动不改变画布 Offset/Zoom，不写画板视口，不改变选择、裁剪会话或 Topmost。
- 进入窗口拖动后抑制右键菜单；松手后不补弹菜单。

### 1.4 固定相框式裁剪

进入：单选图片 → 右键 → 裁剪 → 裁剪模式。

进入后：

- 图片对象外框、位置、尺寸、旋转和层级保持不变。
- 选择描边变成 2 DIP 橙色；四角/四边变换手柄全部隐藏。
- 图片框内出现短提示：“滚轮缩放 · 拖动移动 · Enter 完成 · Esc 取消”，约 2 秒后淡出。
- 框内鼠标指针使用抓手；拖动中变为抓取状态。

框内操作：

- 滚轮向上以指针为锚放大图片；滚轮向下缩小。
- 最小倍率是刚好覆盖外框且不露空白；最大倍率是该最小倍率的 8 倍。
- 左键拖动移动图片在相框中的显示位置；四个方向均钳制，永不露空白。
- 图片有旋转时，鼠标位置先逆旋转到对象本地坐标，再换算为规范化源图位置。
- 图片高清源在裁剪期间到达时，只替换位图源，不改变当前视口、倍率或偏移，不产生闪跳。

完成和取消：

- `Enter`、双击框内图片、右键“完成裁剪”或点击框外：保存并退出。
- `Esc`或右键“取消裁剪”：恢复进入前裁剪值并退出，不产生撤销记录。
- 切换画板、关闭窗口：保存当前裁剪后继续。
- 完成时把临时源图视口换算为 `CropLeft/Top/Right/Bottom`，只写一次数据库并产生一条撤销记录。
- “重置裁剪”把源图视口恢复为当前外框下的居中最小覆盖状态；可撤销。

渲染约束：

- 裁剪手势过程中不得创建新的 `CroppedBitmap`、不得移除/重建 WPF 图片元素、不得触发磁盘解码。
- 使用未裁剪源图加临时 `Viewbox`/变换层实时显示；提交或普通渲染时可以复用同一规范化源图矩形。
- 旧数据先转换为“当前真正可见的有效源图矩形”；仅打开画板不重写历史数据，用户完成一次新裁剪后再保存规范化结果。
- 当前框比例与自然图比例不同时，不允许通过拉伸图像消除空白；必须采用等比覆盖和最小必要裁切。

## 2. 技术方案与修改边界

### 2.1 建议新增的纯逻辑对象

- `BoardResizeGesture`：初始外框、手柄、修饰键、最小尺寸、当前目标外框。
- `BoardCropViewport`：规范化源图矩形、自然像素尺寸、对象框尺寸、倍率与平移钳制。
- `BoardCropSession`：图片 ID、进入前快照、临时视口、是否改变、完成/取消状态。
- `BoardWindowDragPolicy`：右键修饰键、窗口状态、6 DIP 阈值、还原矩形和指针锚点。
- `BoardSceneSnapshot`：画板图片与便签的统一撤销快照；若现有撤销结构可无风险扩展，允许使用等价名称。

### 2.3 数据模型决定

- 优先复用 `CropLeft/Top/Right/Bottom`，其共同表达规范化源图矩形：`X=Left`、`Y=Top`、`Width=1-Left-Right`、`Height=1-Top-Bottom`。
- 图片尺寸继续使用 Width/Height；便签继续使用既有 Width/Height。
- M8.2 默认不增加 schema、不迁移真实图库、不批量改写历史画板。
- 如果实现证明四边裁剪字段无法无损表达确认交互，必须停止该父步骤，在本文档记录反例与备份/迁移方案，不能自行增加数据库字段。

### 2.4 禁止的实现捷径

- 不得通过增大截图中的圆点但保持错误命中层来假装修复。
- 不得只调用 `ResizeBounds` 单测或直接调用事件处理函数就声称真实拖动通过。
- 不得在裁剪滚轮或拖动的每一帧重建 `BitmapSource`、WPF 元素或写数据库。
- 不得用 `Stretch=Fill`拉伸图片来满足裁剪框。
- 不得让 Ctrl+右键窗口拖动复用画布 Offset 变化后再“视觉上看起来移动”。
- 不得降低 M5 视口查询、M7.2 缓存、M8 帧和无黑场门线。
