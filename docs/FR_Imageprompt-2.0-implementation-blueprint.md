## 1. 进度维护规则

### 1.1 状态格式

- `[ ]`：未完成。
- `[x]`：已经完成并通过该步骤规定的验证。
- 正在处理但尚未验收时，复选框保持 `[ ]`，在步骤下添加 `状态：进行中`。
- 遇到阻塞时，复选框保持 `[ ]`，添加 `状态：阻塞`、具体原因和解除条件。
- 不允许因为“代码已经写了”就勾选；构建、测试、数据安全和该步骤验收条件全部通过后才能标记 `[x]`。

### 1.2 完成记录格式

每个已完成步骤必须在原步骤下追加：

```text
完成记录（YYYY-MM-DD）：
- 结果：
- 主要文件：
- 验证：
- 真实数据：
- 数据安全：
- 遗留问题：
- 后续反馈记录：
- 提交或工作区状态：
```

强制要求：

- “真实数据”必须来自本步骤实际执行的构建、测试、基准、日志或真机界面测量，写明测试规模、机器/显示环境、改动前后数据和原始记录路径；禁止用估算值代替实测值。
- 没有适用量化指标的步骤也必须写“无适用量化指标”及原因，不能留空。
- “后续反馈记录”用于保存本步骤暴露但不属于当前范围的现象、用户主观反馈、复测触发条件、下一步骤需要继承的参数和观察点。暂时没有新增反馈时明确写“暂无”，后续收到反馈直接追加，不能覆盖旧记录。
- 性能或稳定性步骤的详细原始结果应写入 `docs/performance/`，蓝图保留关键数字、结论和文件路径。
- 只有上述字段、该步骤验收和第 12 节验证全部完成后，才允许把复选框改为 `[x]`。

如果步骤只完成一部分，必须拆出新的子步骤，不能模糊地将父步骤整体勾选。

### 1.3 新对话接手流程

新的 Codex 对话开始实施前必须：

1. 阅读根目录 `AGENTS.md`、`README.md` 和本文档。
2. 检查 `git status --short`，保留并识别用户已有修改。
3. 从“总进度”中找到依赖已经完成的第一个未勾选步骤。
4. 阅读该步骤列出的现有实现文件，不凭蓝图直接重写。
5. 开工前将该步骤标为“状态：进行中”。
6. 完成后运行该步骤和文档第 12 节要求的验证。
7. 更新复选框、完成记录、真实数据、数据安全、遗留问题、后续反馈记录和文档末尾的实施日志。
8. 如果实际实现迫使产品决策改变，先在第 5 节增加决策记录，再修改路线图。

## 2. 已确认的产品北极星

FR_Imageprompt 2.0 不再以“提示词收录表单”为产品中心，而以沉浸式看图、筛选和整理为核心。收录、数据库维护和 AI 分析退到后台，在用户需要时才出现。

目标主流程：

1. 启动后直接进入无边框、低干扰的瀑布流图库。
2. 图片默认不带永久文字栏；悬停约 200ms 后出现半透明信息层。
3. 单击选中并显示右侧轻量检查器。
4. 双击或按空格进入沉浸式大图。
5. `Ctrl+C` 复制提示词，鼠标中键快速复制提示词。
6. `Ctrl+F` 呼出 Everything 风格即时搜索；`Ctrl+K` 呼出命令面板。
7. 复制图片后只显示右下角轻量收录胶囊。
8. 捕获下一段完整文本，稳定约 600ms 后自动保存。
9. 重复图片静默更新，只显示小字状态。
10. 两分钟没有提示词时，图片进入“待补提示词”收件箱，不删除。
11. AI 在后台生成分类、标签、描述、审美属性和语义向量。
12. AI 结果可立即校正；未处理结果进入“待校正”智能集合。
13. 图库图片可以发送到多个命名自由画板，进行摆放、缩放、分组和保存。

不可妥协原则：

- 浏览过程中画布不能整体闪黑、清空或重建。
- 自动化必须无感，但所有结果必须可撤销、可校正。
- AI 只产生有来源的草稿，用户确认结果永远优先。
- 30,000 张图片、4K 分辨率和 150% Windows 缩放是基础验收环境。
- 当前图库默认安全迁移并自动备份；不得为了开发方便直接丢弃用户数据。
- 不因“重构更彻底”盲目更换 WPF；只有性能门槛实测无法达到时才评估替代渲染方案。

## 3. 已确认的用户环境与规模

- 当前图库：约 600 张。
- 一年目标：约 30,000 张。
- 收录图片：通常约 2MB/张。
- 外部文件夹图片：通常约 5MB/张。
- GPU：NVIDIA GeForce RTX 5090，32GB 显存。
- 内存：96GB。
- 显示器：4K。
- 当前检测到的 Windows DPI：144 DPI，约等于 150% 缩放。
- 使用定位：个人长期主力工具；质量足够高时可能分享给其他用户。
- 允许中期重构，但所有破坏性数据库变更仍须先备份并提供恢复路径。

## 4. 已确认的主要问题

### 4.1 搜索和分类切换闪烁

M1-05 改造前，刷新会替换图库行、重新创建卡片和缩略图加载状态，并播放整层透明度动画，结果切换时会短暂露出黑色背景。M1-05 已改为稳定 ID 差分、卡片与缩略图复用、首屏准备后同步提交，并移除整层透明度动画；零结果使用明确空状态。

相关实现：

- `src/PromptVault.App/MainWindow.xaml.cs`
- `src/PromptVault.App/ViewModels.cs`
- `src/PromptVault.App/Services/ThumbnailCache.cs`

目标：稳定 ID 差分、ViewModel 复用、首屏优先、缩略图准备后局部更新，禁止整层黑场过渡。

### 4.2 提示词剪贴板事件丢失

当前图片处理期间 `_processing=true`，后续剪贴板更新不会进入处理逻辑，因此用户紧接着复制的提示词可能被忽略。

相关实现：

- `src/PromptVault.App/Services/ClipboardMonitor.cs`
- `src/PromptVault.App/Services/CaptureCoordinator.cs`

目标：事件队列、剪贴板序号、最新文本缓冲和可恢复的捕获状态机。

### 4.3 隐藏菜单不跟手

当前顶部和左侧面板分别使用固定 280ms 呼出和 1000ms 收回定时器，不能识别鼠标意图。

相关实现：

- `src/PromptVault.App/MainWindow.Chrome.cs`

目标：边缘意图识别、速度与停留判断、安全移动走廊、键盘命令入口和可调灵敏度。

### 4.4 大图库承诺尚未兑现

- M1-01 已改为准确总数、首批数据和稳定键游标。
- M1-02 已启用 FTS5 trigram，并将正常启动从重复全量重建改为只校验索引状态。
- M1-03 已接入 240 条首批数据、稳定键增量取页、约两屏预取和回收式 WPF 行容器；只为已实现行创建卡片 ViewModel。
- 30,000 张面板原型达到帧率门槛，继续采用 WPF，不在此阶段引入自定义虚拟化瀑布流 Panel。
- M1-04 已改为固定工作线程、可见区优先、两屏预取、取消与请求合并；解码缓存按 384MiB 字节预算淘汰，并根据实际 DPI 使用 480px/1600px 档位。
- M1-05 已移除搜索与分类切换的整层淡入和无条件对象重建；旧图库保持到新首屏 42/42 卡片就绪，逐帧检查 208 帧中近黑帧为 0。
- M1-06 已将外部文件夹改为持久化增量索引；刷新只查询 SQLite，不再枚举目录或逐张读取尺寸。首次扫描在后台读取文件头，未变化复检按路径、大小和修改时间跳过图片读取，文件监控增量处理新增、修改、重命名和删除。
- M1-07 已完成 30,000 张、4K/150% 真界面总门禁：冷启动、搜索、分类、滚动、沉浸大图、缩略图内存与约 5MB 大图解码全部通过；59Hz 真机标准滚动 P95/P99 为 16.949/33.064ms，缩略图缓存为 206.158/384MiB。

M1 目标已完成：FTS、游标分页、准确总数、真正的 UI 与数据虚拟化、增量外部目录索引以及真机性能门禁均有可重复证据。

### 4.5 回收站自动清理遗留文件

当前 30 天清理只删除 `collection_items`，不会完整清理对应 `image_assets` 与图片文件，可能形成孤立资源。

相关实现：

- `src/PromptVault.Core/LibraryRepository.cs`

目标：在事务中收集并删除符合条件的 asset，提交后安全删除文件，并提供孤立资源检查工具。

### 4.6 AI 重复加载且结果不可追踪

- 每次建议都会重新读取 manifest 并创建 ONNX Session。
- 模型异常被统一回退，用户无法知道真实状态。
- AI 建议与用户确认数据没有独立来源和状态。

相关实现：

- `src/PromptVault.App/Services/LocalAiClassifier.cs`
- `src/PromptVault.App/CaptureWindow.xaml.cs`
- `tools/model-pack/`

目标：独立 AI Worker、持久任务队列、模型常驻策略、来源/版本/置信度、草稿与用户确认分层。

## 8. 数据模型规划

最终 schema 名称可以在实现时按现有命名风格调整，但必须覆盖以下概念：

- `capture_inbox`：待补提示词与未完成捕获会话。
- `ai_jobs`：持久 AI 队列、状态、重试和模型版本。
- `metadata_candidates`：AI 或规则生成的候选元数据。
- `user_metadata` 或现有字段扩展：用户确认的权威元数据。
- `image_embeddings`：向量、模型版本和维度。
- `boards`：命名画板。
- `board_items`：图片引用及变换。
- `board_groups`：画板分组。
- `view_preferences`：按图库或外部文件夹保存布局、密度和排序。
- `external_file_index`：外部文件夹增量索引。

要求：

- 所有迁移必须可测试、可备份、可失败恢复。
- AI 派生数据和向量索引可以重建。
- 用户提示词、标签、备注、确认结果和画板布局属于不可随意重建的用户数据。

## 9. 视觉与交互约束

- 主背景使用中性近黑色，让图片颜色成为视觉主体。
- 科技感来自精确动效、层次和反馈，不依赖大面积霓虹。
- 青色仅用于焦点、选中、进行中和可操作状态。
- 卡片默认无永久标签底栏。
- 悬停信息层不能触发布局变化。
- 禁止为了掩盖加载而整体淡出图库。
- 面板动效优先使用 Transform 和 Opacity，谨慎使用大面积实时阴影。
- 支持减少动效设置。
- 所有隐藏功能都必须有键盘入口或可发现提示。
- 4K、150% 缩放是默认设计与测试环境。

## 10. 性能验收指标

在 30,000 张测试图库、4K、150% 缩放环境下：

- 冷启动到首屏可见：不超过 1.5 秒。
- 搜索或分类切换首屏更新：P95 不超过 80ms。
- 已缓存沉浸大图切换：不超过 100ms。
- 首次磁盘大图解码：目标不超过 300ms。
- 滚动：60Hz 名义门槛为 P95 不超过 16.7ms、P99 不超过 33ms。真机显卡驱动报告的刷新率为 `R` 时，以 `T = 1000 / R` 校准，P95 不超过一个 `T`、P99 不超过两个 `T`；必须同时记录名义值、刷新率、`T` 和原始毫秒结果，超过两个真实刷新周期一律失败，不得从卡顿样本反推刷新率。
- 不出现整层全黑或接近全黑的刷新帧。
- 有意呼出菜单：90–140ms。
- 缩略图内存缓存：不超过 512MB 默认预算。
- 相似图片搜索：不超过 100ms。
- 剪贴板图片事件：100ms 内出现状态反馈。
- 混合剪贴板压力测试：零丢失、零重复保存。
- AI 推理不得在 UI 线程产生超过 16ms 的阻塞。

如果某指标在真实机器上不合理，必须先记录测量证据、瓶颈和调整理由，再修改本节，不能静默降低标准。
