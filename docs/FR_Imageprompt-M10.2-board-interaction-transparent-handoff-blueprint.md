## 1. 已确认的产品契约

### 1.1 图片默认等比缩放

- 适用单图、组合和多选共同外框的四个角；保持 M8.3 的 28 DIP 命中区和手势所有权。
- 默认拖角保持比例；比例因子以按下时的原始外框、固定指针起点和当前指针在原始对角线方向上的连续投影计算。
- 同一方向连续拖动时，尺寸必须单调连续；不得按水平/垂直变化量择大而切换主导轴。
- `Shift+拖角`继续自由改变宽高；`Alt+拖角`继续从中心等比；`Shift+Alt`继续从中心自由改变宽高。
- 拖动期间只更新冻结选择集、已实现视觉和选择外框；不得全板 `RenderVisibleItems()`、重建图片视觉、重建位图或写数据库。
- 手势期间临时使用适合运动的位图缩放模式；完成或取消后恢复高清显示。完成时只产生一条撤销记录和一次批量保存。
- 四角、旋转图、横竖极端比例、25%/50%/75%/100%/150% 画布缩放均必须通过。

### 1.2 新建便签与属性

- 只影响以后新建的便签，不迁移或改写已有便签。
- 新建默认尺寸 `420×140 DIP`，默认字号 `32px`，默认垂直边距 `16px`。
- 新建首次确认不再自动把节点缩回内容尺寸；“适合文字内容”仍是用户主动命令。
- 图片和便签的视觉目标必须使用类型安全标识；即使数据库中的图片 ID 与便签 ID 数字相同，右键便签“属性”也只能打开便签属性。
- 属性面板必须显示实际选中便签，不得显示图片原始尺寸、宽高比或裁剪字段。
- 文字颜色与背景颜色使用 WPF 轻量调色浮层：明确的两个色块/按钮、常用色、HEX 输入、实时预览。
- 调色浮层打开时只改当前便签内存与视觉；`Enter`、点击外部或选择颜色后一次提交并形成一条撤销；`Esc`恢复打开前样式。
- 颜色按钮本身保持可读文字与独立色块，不能再把整枚按钮背景直接涂成用户颜色而导致文案消失。
- 不引入字距、自动换行、自动补高、Windows Forms `ColorDialog`、新数据库字段或逐预览写库。

### 1.3 无选择 `Space` 的一层手工相机返回

- 有选择：保持 M10.1 契约；第一次 `Space`立即聚焦当前选择，第二次恢复首次临时视图快照。
- 无选择且存在最近一次已完成的手工平移/缩放：第一次 `Space`返回该手势之前的视图；第二次 `Space`切回返回前视图。
- 只保留一层；新的手工平移或滚轮缩放完成后覆盖上一层。
- 中键、`Alt+左拖`、普通右拖共用一次平移手势边界；连续滚轮按约 250ms 停止合并为一次手势。
- 手工相机历史只存在内存，不写画板数据库、不进入对象撤销栈，也不覆盖 M10 的首次临时视图快照。
- `Ctrl+Space`、`Ctrl+0`、图片双击与 `Esc` 继续使用现有统一临时相机会话，不被本功能改写。

### 1.4 顶部栏唤出与隐藏

- 取消裸 `Alt` 和 `F10` 的顶部栏唤出；文本编辑、菜单和输入法不应被这两个旧入口打断。
- `Alt+Q`立即切换顶部栏显示/隐藏；帮助文案、命令描述和自动化名称同步更新。
- 顶边感应区为 `8 DIP`；指针连续停留 `250ms` 后显示，避免快速掠过误触。
- 指针离开顶部栏和安全走廊后 `500ms` 自动隐藏；菜单、下拉、Popup 或顶栏内键盘交互期间不得误隐藏。
- 顶部栏仍覆盖画布且不参与测量；显示、隐藏均不得改变画布世界坐标或视口尺寸。

### 1.5 主图库透明模式无闪交接

- 普通→透明和透明→普通都必须在任意滚动位置无首屏闪现、无黑帧、无空白帧、无动画。
- 保留 WPF `AllowsTransparency` 需要替换窗口的事实，不通过截图覆盖层伪装。
- 原窗口保持可见，直到替换窗口完成数据接管、布局恢复、滚动锚点恢复、目标虚拟化卡片实现，并连续两个渲染帧稳定。
- 替换窗口预热期间不可激活、不可见；准备完毕后在同一 Dispatcher 交接中显示新窗口、更新托盘目标并关闭旧窗口。
- 透明切换本身布局重排仍为 `0`；列数、卡片尺寸、滚动锚点、选择、已显示位图和 M7.2 缓存协议保持。
- 视觉资源模式只在原子交接点更新，不能让仍可见的旧窗口提前变成目标主题，也不能让新窗口先以普通主题显示一帧。
- 透明模式下用户手工改窗结束后的 `180ms` 单次防抖重排继续保留。

## 2. 根因记录与不可回退边界

### 2.1 已确认根因

1. `BoardTransformEngine.ResizeBounds` 在默认等比缩放中比较 `widthScale` 与 `heightScale` 的偏离量，拖动轨迹越过相等边界时会瞬间切换主导轴，造成图片、选择框和手柄一起跳大或跳小。
2. 图片根和便签根都把裸 `long` 写入 `Tag`；`ResolveRightTarget` 先查图片字典。两个数据库表的 ID 可相同，因此便签会被误判为图片。
3. 新便签仍以 `300×220` 建立，并在首次保存时自动 `FitNoteRecordToContent`，与确认的新建默认契约冲突。
4. 颜色按钮通过 Windows Forms 模态调色器修改，且按钮背景直接使用选中颜色，导致浅色背景上的文字不可见，也无法形成可靠的当前便签预览/撤销边界。
5. 现有 `Space` 只知道临时聚焦会话，不记录普通手工平移/缩放前的相机。
6. 顶栏仍有裸 `Alt/F10` 和立即顶边唤出路径。
7. `App.SwitchMainWindow` 在替换窗口恢复滚动和虚拟化完成前立即 `Show/Activate`，新窗口先绘制初始首屏；`VisualModeService.Apply` 又修改应用级资源，可能提前影响仍可见的旧窗口。

### 2.2 禁止回退

- 不恢复逐帧 `RenderVisibleItems()`、视觉重建、位图重建或 SQLite 写入。
- 不改变固定相框裁剪、Shift 自由拉伸、Alt 中心缩放、普通右拖平移、Ctrl+右拖整窗移动。
- 不改变 M8.5 零常驻边框、单选共同细框、多选成员细框和裁剪橙框。
- 不改变 M7.2 分规模元数据、运动预览、384MiB 高清缓存、虚拟化、旧图保持和无黑场门线。
- 不使用真实图库做验证；不把本机路径、许可证内容、密钥或合成图库实体写入仓库。
- 不新增数据库 schema，不迁移旧便签，不把调色预览写入持久化层。
